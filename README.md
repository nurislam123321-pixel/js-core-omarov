## Что реализовано

### Часть 1 — `src/functions.js`

| Функция | Что делает |
|---|---|
| `unique(arr)` | массив без повторов, через `Set` |
| `groupBy(arr, keyFn)` | группировка объектов по вычисляемому ключу, через `reduce` + деструктуризация + spread |
| `chunk(arr, size)` | разбивка массива на куски заданного размера |
| `deepClone(obj)` | глубокая копия без `JSON.parse(JSON.stringify())`, рекурсивно |
| `memoize(fn)` | кэширование результатов на замыкании (`Map` в замыкании) |
| `counter()` | фабрика счётчика — `inc`/`dec`/`value`, тоже на замыкании |

### Часть 2 — `src/Store.js`

- Класс `Store`: приватные поля `#items`, `#idKey`; методы `add`, `remove`, `find`; геттеры `total` и `items`; статический метод `Store.from(...)`.
- Класс `SortedStore extends Store`: переопределяет геттер `items`, вызывает `super.items` и сортирует результат переданной `compareFn`.

### Часть 3 — тесты (`tests/`)

22 теста в сумме (по заданию нужно минимум 12), с edge case'ами:

## Замыкания в моём коде

Замыкания я использовал в двух местах — `memoize` и `counter`. В `memoize` внутренняя переменная `cache` (это `Map`) создаётся один раз при вызове `memoize(fn)`, и возвращаемая функция `memoized` "помнит" эту переменную между вызовами — снаружи до `cache` достучаться нельзя, только через саму `memoized`. Это и есть суть замыкания: внутренняя функция держит ссылку на переменные из внешней области видимости, даже после того как внешняя функция уже отработала и завершилась. В `counter()` то же самое происходит с переменной `count`: каждый вызов `counter()` создаёт свою собственную, изолированную копию `count`, поэтому два разных счётчика (`counter()` и `counter(10)`) не мешают друг другу — я это специально проверил в тесте. Без замыкания пришлось бы либо делать `count` глобальной переменной (тогда все счётчики делили бы одно состояние — плохо), либо оборачивать всё в класс с явным полем — замыкание даёт то же самое короче и без синтаксиса класса. Разница с обычной локальной переменной в том, что обычно локальная переменная функции исчезает сразу после return, а тут она "выживает", потому что возвращаемая функция продолжает на неё ссылаться.
